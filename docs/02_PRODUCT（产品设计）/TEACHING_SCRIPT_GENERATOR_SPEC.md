## 1. 这个系统解决什么问题

Teaching Layer 的 4 类模板已上线（S71/S72），但 `overlay_hints` 目前**没有生产者**——规则解析器不填，18 个现有场景全靠渲染层的"缺省推导规则"兜底。

缺省推导的问题是：
- 推导逻辑散落在渲染层，不可测试、不可调优；
- 未来 AI 生成场景时，没有统一的"教学脚本"产出物与质量校验关口。

**TeachingScript Generator = 从 PhysicsScene 自动生成 overlay_hints 的规则系统。**
它是 P1 定稿决策（"AI 负责选择和组合模板"）的承载物：先规则生成（确定性、可测试），后 AI 接入（AI 输出同结构，规则系统作为校验与兜底）。

## 2. 系统设计

```
PhysicsScene（唯一数据源，不变）
     │
     ▼
TeachingScript Generator（规则系统，新增纯函数模块）
     │  输出 TeachingScript = overlay_hints + 文案
     ▼
Validator（校验器：字段引用存在性 / 字数 / 数量上限）
     │  校验失败 → 回退缺省推导
     ▼
Teaching Layer（已有渲染层，消费 overlay_hints，不变）
```

**关键设计决策**：
- 生成器与校验器为**纯函数**，放在 `packages/shared` 或渲染层 lib，供规则解析器、未来 AI 管线、测试三方复用。
- 规则解析器生成场景后**顺带调用生成器**，把 overlay_hints 写进场景（显式产出，替代渲染层隐式推导）；已有 18 个场景通过一次性迁移/运行时生成获得教学脚本。
- AI 未来接入时只替换"生成器"内部实现，上下游不变。

## 3. 生成规则集

| 规则 | 输入 | 输出 | 说明 |
|------|------|------|------|
| R1 阶段卡 | 每个 timeline phase | `phase_cards[]` | title=phase.label；hint=phase.description，缺失则不生成 hint（不硬编文案） |
| R2 公式条 | equations + phases | `formula_strips[]` | 缺省 phase[i]↔equations[i]；改进匹配：`is_solution` 公式固定归最后一个 phase；`type:"energy"` 优先匹配能量相关 phase（按 phase label 关键词） |
| R3 受力标注 | forces + phases | `force_callouts[]` | phase 内 active 的力 → label + magnitude 公式；按大小排序，显式标注前 3，其余进 "+N" |
| R4 事件脉冲 | timeline.events | `event_pulses[]` | collision 必标 + 每 phase 首个其他关键事件（state_change/trigger），每 phase ≤2 |

## 4. 质量约束（校验器规则）

1. 每 phase 教学元素总量上限：1 阶段卡 + 1 公式条 + ≤3 受力标注 + ≤2 事件脉冲（防信息过载）。
2. 文案长度：hint ≤30 字；事件解释 ≤20 字。
3. 引用完整性：所有 `phase_id` / `equation_id` / `force_id` / `event_id` 必须存在于场景中，否则丢弃该条目。
4. 校验不通过：逐条丢弃违规项；若某模板整组失效，回退渲染层缺省推导（现有行为，保证永远可用）。

## 5. 教学体验意图（为什么这些规则是对的）

- **R1** 保证学生任何时候都知道"我在哪一步"——阶段感是教学叙事骨架。
- **R2 的 solution 归末段**：答案公式只在过程演完时出现，符合"先理解后答案"（理解 > 答案）。
- **R3 的前 3 限制**：受力全标会糊满屏幕；初高中场景主受力 rarely 超过 3 个。
- **R4 的 ≤2 限制**：脉冲是"注意力武器"，滥用即失效。

## 6. 工程实施要点（S74）

1. 新建纯函数模块：`generateTeachingScript(scene): OverlayHints` + `validateTeachingScript(scene, hints): OverlayHints`。
2. 规则解析器管线末尾接入生成器；18 个内置场景可运行时生成（无需改写场景文件）。
3. 渲染层缺省推导保留为最终兜底，但优先消费显式 overlay_hints。
4. 测试：对 18 个内置场景快照测试（生成结果确定性）；校验器单测（引用缺失/超长/超量的丢弃行为）。
5. 不修改 PhysicsScene 任何现有字段；overlay_hints 仍为可选。

## 7. 验收要点（设计侧，S74 走查用）

1. 18 个内置场景播放时教学图层均有合理内容，无空 phase 卡片、无悬空引用。
2. solution 公式只出现在最后一个 phase。
3. 任意场景每 phase 元素总量不超上限。
4. 人为构造非法 overlay_hints，校验器正确丢弃并回退。

## 9. S75 范围（2026-08-05 已确认）：AI 接入 TeachingScript

**AI 允许**：① 文案润色（hint/事件解释改写为中学生友好口语）；② 模板组合开关（按题型关闭不必要模板）。

**硬边界**：
1. AI 输出必须过 `validateTeachingScript`，失败整体回退规则版本；
2. Ollama 离线/超时无感知降级规则版；
3. R1-R4 教学规则为红线（solution 归末段等），AI 只可润色与开关，不可重排。

**文案风格约束**：中学生口语化；hint ≤30 字 / 解释 ≤20 字（校验器强制）；引导式优先（"观察…/注意…"）；末段前不剧透答案数值。

**S75 验收要点**：AI 在线文案更口语更引导且不剧透；离线无感知回退；非法 AI 输出被拦截回退。
