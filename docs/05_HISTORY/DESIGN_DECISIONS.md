## 2026-08-03 · DD-001 · 首次体验审计与四项设计提案

**背景**：项目于 2026-08-03 重新定位为 Physics AI Engine（输入题目 → AI 自动生成教学动画）。产品体验与视觉设计 Agent 对当前产品（V4.6 / S69）进行首次审计。

**核心判断**：当前 UI 为"实验驱动"架构（首屏=实验模拟器+实验切换器），与新定位的"题目驱动"核心主线错位。PhysicsScene 数据结构（phases / teacher_steps / equations / camera_script）已具备教学叙事能力，瓶颈在呈现层设计而非技术。

**提出的长期设计方向**（待项目负责人批准）：

1. **题目优先的信息架构**：题目输入应成为启动首页，实验库降级为二级入口。核心闭环必须在 UI 第一路径上可被感知。
2. **Hybrid 2D+3D 的呈现定义**：3D 画布负责空间结构；2D 图层（HTML/SVG，Timeline 驱动）负责阶段卡、受力标注、公式推导。信息必须出现在"它解释的物体旁边"，而不是分离的侧面板。低性能场景降级为面板联动。
3. **渐进式复杂度**：默认界面极简（画布+Timeline+讲解入口），高级能力按需展开；不做功能堆砌。
4. **教学语义色表**：颜色是教学语言（红=力、青=速度、琥珀=能量、橙=关键事件），全项目统一，跨实验形成稳定视觉直觉。

**详细方案**：见 `docs/02_PRODUCT（产品设计）/UX_AUDIT_AI_ENGINE.md`

**状态**：✅ 已采纳（2026-08-03 项目负责人确认全部四项决策）。

**确认时的重要细化**：
- P0：Physics Lab 实验库明确为二级功能入口，全部能力保留。
- P1：Teaching Layer 定为**模板系统**——AI 只负责选择和组合模板、填充参数，不直接生成教学视觉内容。此决策保证视觉质量稳定可控，并为未来 AI 教学脚本预留结构。
- P2：取消平级三模式；学习模式为默认核心入口，实验/解析为高级能力。
- P3：五色语义系统确认，且颜色规则**对用户隐藏**——系统一致表达，不增加用户学习成本。

**实施结果**（2026-08-04 回填）：✅ P0-P3 已全部落地。
- S71：题目输入首页 + PhaseCard/FormulaStrip（验收通过，4 项实施偏差批准，见 TEACHING_LAYER_SPEC §8）
- S72：ForceCallout/EventPulse + P2 第一步（三模式退出顶栏、IconRail、实验库抽屉化）（验收通过，§9）
- S73：语义色系统双主题落地 + FormulaDisplay 变量着色（验收通过）
- S74 启动：TeachingScript Generator（overlay_hints 规则生成系统），规格 TEACHING_SCRIPT_GENERATOR_SPEC.md。产品形态正式从"实验模拟器"转为"题目驱动的教学动画产品"。

## 2026-08-20 · DD-002 · AI 部署方向：从纯本地转向"本地应用 + 云端 AI"（待最终确认）

**背景**：S75-S79 实测证明 llama3.2（3B 本地模型）撑不起核心承诺（"任意题目→正确教学动画"）；润色功能经两轮修复才稳定。项目负责人 2026-08-20 提出："先放弃完全本地方向，做成本地需要联网的应用，完全离线版作为大后期拓展。"

**设计侧立场（背书）**：同意。理由：
1. 核心价值（题目→正确动画）的瓶颈是模型能力，3B 本地模型在当前硬件上无法达标；
2. 架构不受冲击——现有 AIProvider 抽象可直接新增 CloudProvider，降级链（云端→本地→规则版）不变；
3. "纯本地"从默认档降为可选档，产品形态从"离线优先"转为"联网优先、离线兜底"。

**UX 配套要求**：设置页 API key 配置；首页 AI 状态三态提示（云端/本地/离线降级）；解析失败永远诚实提示而非硬凑动画（教学红线）。

**状态**：✅ 已采纳（2026-08-20 项目负责人确认，S85 启动）。

**配套决策（同日确认，源自 Hammerath 风格研究 HAMMERATH_STYLE_STUDY.md）**：
- **B2 积分制商业模式**：生成按次计积分（与云 AI 成本结构契合），可与订阅制混合（免费额度 + 超出按次）；MVP 阶段不做积分 UI，先评估与成本测算。
- **B1 双轨视觉策略**：桌面端保持深色主题（教学场景长时间注视需要），引入浅色风的留白与呼吸感（并入 S86 质感攻坚）；未来营销官网/Web 版采用 Hammerath 式浅色极简。不修改 FOUNDATION（UI_GUIDELINES 深色规范仅约束桌面应用）。
- **B3 真实班级试用里程碑**：找 1-2 个真实班级试用，素材反哺未来官网/宣传（"教育实践"信任区）。
- **A 类 UX 细化（全部批准）**：漂浮物理符号等待动画、编号步骤进度条、首页品牌副标、CTA 精简为「一键生成」。

## 2026-08-28 · DD-003 · 动画系统重做：Hybrid 2D+3D 教学动画（✅ 已定稿）

> ⚠️ 注：本文件疑似被回滚至较早快照（DD-001 实施回填至 S74、DD-002 缺 S85 完成回填），DD-003 按最新事实记录；请项目负责人确认是否为有意回滚。

**背景**：S86 质感验证未通过（项目负责人亲测 2026-08-28：相机不灵活、节奏难掌控、动画太快学生会晕头转向、视觉笨拙）。根因不是质感参数，而是单一 3D 渲染路径承载所有教学表达——平面物理问题被强行 3D 化。

**方向决策（项目负责人拍板，2026-08-28）**：
1. **平面问题 → 纯 2D**：简单二维物理过程直接生成 2D 矢量动态图解，不经过 3D；
2. **空间问题 → 可切换的 3D+2D 叙事流**：阶段 A 3D 自由观察建立空间直觉（拖动旋转相机）→ 阶段 B 锁定视角（旋转到合适角度后锁定）→ 在该视角投影平面上进行 2D 动画教学演示；
3. **2D 视图是重新生成的矢量图解**，不是隐藏 3D 模型；2D/3D 不是二选一、不是孤立系统——3D 建空间直觉，2D 做物理解释；
4. **视觉风格定稿**：「极简扁平矢量科学可视化」/「Physics Diagram Motion Graphics」/「Scientific Infographic Motion Graphics」——会运动的物理示意图；扁平化/矢量化/几何化/极简；禁卡通/Q版/影视/写实3D/游戏风/PPT模板/大量装饰与渐变光影；少即是多；
5. **动画必须承担"解释物理"的职责**：速度/加速度/力/位移/轨迹/能量优先通过物体运动、矢量变化、轨迹变化、辅助线和动态标注表达，而非只靠文字；
6. **运动连续性**：避免突然的出现/消失、机械淡入淡出和 PPT 式转场；运动有合理时间关系、缓动和连续性；
7. **音效**：轻量事件音效（碰撞/弹簧/启停/关键事件/操作反馈），克制不干扰，全局开关；关闭音效后动画必须能完整表达物理意义。

**设计规格**：`02_PRODUCT（产品设计）/HYBRID_2D3D_ANIMATION_SPEC.md` v0.9（含 D1-D4 决策、视觉语言规格、节奏 R1-R5、相机 C1-C5、判定规则、3D→2D 过渡、音效规格、工程移交要点、验收要点）。

**决策点确认（2026-08-28 项目负责人拍板，全部采纳推荐方案）**：Q1=平面题纯 2D 不做 3D；Q2=默认播放速度 0.8x 基准（走查标定）；Q3=音效默认关闭一键可开；Q4=S87 快修包（节奏 R1-R5+相机 C1-C3/C5，作用于现有 3D 系统）→ S88+ 建设 2D 动画系统。**S87 已移交工程实现 Agent（第 18 轮，留言 27）**；S85 云 AI 实测为独立主线，待 API key。
