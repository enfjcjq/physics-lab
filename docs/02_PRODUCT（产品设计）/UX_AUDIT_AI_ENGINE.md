## 0. 审计结论（一句话）

> 当前产品是一个**优秀的"交互式物理实验平台"**，但还**不是**"AI 物理教学动画生成引擎"。
> 用户打开产品后首先看到的是"18 个实验的模拟器"，而不是"输入一道题，看它活过来"。
> 核心主线（输入题目 → AI 生成教学动画）在 UI 上不是第一路径——这是当前最大的体验问题。

---

## 1. 现状审计：与核心定位的三个错位

### 错位 1：入口错位 —— 产品"首页"是模拟器，不是题目输入

**事实**（基于 `App.tsx` / `AppShell.tsx` 代码）：
- 应用启动后直接加载上次的实验插件（默认自由落体），用户第一眼看到的是 3D 场景 + 面板群。
- 题目输入（含 OCR）已存在，但只是左侧面板中的一个功能，不是主路径。
- 顶栏最显眼的控件是"实验切换器"（18 个实验下拉列表）——这是模拟器产品的信息架构。

**与定位的冲突**：核心闭环是"**题目驱动**"，而当前 UI 是"**实验驱动**"。学生带着一道不会的题来，却被要求先"选一个实验"。

### 错位 2：动画是"演示运动"，还不是"解释为什么"

**事实**：
- 3D 场景已有：实体、轨迹、受力箭头、HUD、碰撞粒子——属于"展示物体如何运动"。
- PhysicsScene 数据结构**已经具备**教学叙事所需的全部字段：`timeline.phases`、`teacher_steps`、`equations`、`camera_script`。
- 但渲染层还没有"阶段化教学叙事"：没有阶段标题卡、没有"为什么"的自动讲解提示、没有公式随时间推导的呈现。
- **Hybrid 2D + 3D 尚未实现**：目前只有 3D 场景 + 独立面板，没有"讲解时切换/叠加 2D 教学视角"的能力。

**与定位的冲突**：视觉方向要求"3D 理解空间结构，2D 理解公式、受力和过程"。当前的 2D 信息（公式、步骤）躺在侧边面板里，与动画时刻脱节。

### 错位 3：界面信息密度偏高，偏离"少即是多"

**事实**：首屏同时存在——MenuBar、三模式切换（学习/实验/分析）、实验切换器、左面板、右面板、教师面板、底部抽屉、Timeline、Dashboard 弹层、成就 Toast。对第一次打开的学生，认知负担重。

**与定位的冲突**：PRODUCT_PRINCIPLES 第十一条："学生第一次打开就知道如何使用"。

## 2. 已定稿设计方案

> 以下方案已经项目负责人于 2026-08-03 确认定稿。
> 所有方案**不修改物理计算逻辑、不改变基础架构**（PhysicsScene 数据驱动、Timeline 驱动、插件系统均保持不变），改动集中在渲染层与信息架构。

---

### P0（已定稿）：题目优先 —— 题目输入页成为启动首页

**决策**：采用方案 A。首页改为题目输入页；Physics Lab 实验能力（18 个实验）作为**二级功能入口**保留，不作为核心入口。

**定稿方案**：
```
启动
 ↓
┌─────────────────────────────────────┐
│  "把不会的物理题放进来"               │
│  ┌───────────────────────────────┐  │
│  │  输入题目文字 / 拍照(OCR)       │  │   ← 首屏唯一主角
│  └───────────────────────────────┘  │
│  [开始生成教学动画]                   │
│                                      │
│  最近题目 ▸   示例题目 ▸   实验库 ▸  │   ← 二级入口，折叠呈现
└─────────────────────────────────────┘
 ↓ 生成中：分步进度（识别实体 → 建模 → 编排动画）
 ↓
学习场景页（教学动画 + Timeline + 讲解，默认即"学习模式"）
```

**设计要点**：
- 首屏只有一个主行动：输入题目。实验库、最近题目、示例题目均为折叠的次级入口。
- 进入学习场景页后，实验切换器从顶栏一级位置移除，收进"实验库"抽屉。
- 老用户连续性：通过"最近题目"和"实验库"保留原有使用路径，不删除任何既有能力。

**学习体验提升**：学生的真实场景是"作业里有一道题不懂"。首页让产品从"我来逛实验"变成"我的题活了"，核心卖点（AI 生成教学动画）在第一次启动时即可被感知。

**技术实现需求**（移交工程）：
- 新增首屏组件（题目输入 + OCR 入口 + 最近题目列表），复用现有 problem-input 与 OCR 能力，不新增 AI 依赖。
- 页面切换沿用 Zustand 状态驱动（维持无 React Router 约定）。
- 生成过程展示分步进度（现有 progress 事件已支持）。
- 不改动 PhysicsScene 结构、解析器、插件系统。

---

### P1（已定稿）：模板化 Teaching Layer —— Hybrid 2D+3D 落地方式

**决策**：采用模板化教学图层（Teaching Layer）。短期建立**教学动画解释模板系统**；AI 的职责是**理解题目后选择并组合模板、填充参数**，不直接生成全部教学视觉内容。

**定稿方案**：

**架构定位（设计层，不改引擎架构）**：
```
PhysicsScene（唯一数据源，不变）
     │  phases / forces / equations / timeline.events / camera_script
     ▼
Teaching Layer（新增渲染层：模板选择 + 组合 + 驱动）
     │
     ├── 3D 场景：空间结构、实体运动（现有，保持）
     └── 2D 教学图层（新增，HTML/SVG，叠加在 3D 画布上，由 Timeline 驱动）
```

**模板库（第一批，每类模板 = 数据槽位 + 呈现规则 + 出现时机）**：

| 模板 | 作用 | 数据槽位（来源字段） | 出现时机 |
|------|------|----------------------|----------|
| 阶段卡 PhaseCard | 告诉学生"现在进行到哪一步" | phase label + 一句话解释（timeline.events） | 每个 phase 开始，动画自动减速/暂停一拍 |
| 受力标注 ForceCallout | 解释"为什么受力" | 力的名称、大小公式、方向（forces[]） | 镜头推近物体时；箭头旁 2D 标签，不参与 3D 透视变形 |
| 公式推导条 FormulaStrip | 展示"规律如何产生" | 公式 LaTeX + 变量代入值（equations[]） | 画布底缘，随时间逐步展开：先式子 → 代入数值 → 高亮结果 |
| 事件标记 EventPulse | 强化关键时刻（碰撞、射出、换向） | 事件描述（timeline.events: collision 等） | 事件发生帧，橙色脉冲 + 一行解释 |

**AI 职责边界（长期）**：AI 输出"用哪些模板、顺序、填入什么参数"（结构化选择），模板负责视觉呈现。这样保证视觉质量稳定可控，同时为未来 AI 生成教学脚本预留了结构。

**降级策略**：低性能设备或模板未配置的实验，自动退回"3D 场景 + 侧面板联动高亮"（现有能力增强），保证任何场景可用。

**开关**：所有 2D 教学元素支持显示/隐藏（原则十二：教学内容可自由控制）。

**学习体验提升**：从"看运动"升级为"被带着理解"——阶段卡讲进度，受力标注讲原因，公式条讲规律，事件标记讲关键。信息出现在它解释的物体旁边，学生视线不再在场景与侧面板之间来回跳。

**技术实现需求**（移交工程）：
- 新增 Teaching Layer 渲染组件（纯渲染层，订阅 Timeline 当前时间与 phase 事件）。
- 模板数据从现有 PhysicsScene 字段映射；如需新增字段，仅**追加**可选字段（建议名 `teaching_hints`），向后兼容，需与工程 Agent 确认。
- 阶段自动减速/暂停由 Timeline 播放控制扩展实现，不改物理计算。

### P2（已定稿）：信息架构两步走 —— 学习为默认，实验/解析为高级能力

**决策**：采用两步走方案。保留学习/实验/解析全部能力，但**取消平级三模式**。学习模式作为默认核心入口；实验（参数调节、3D 探索）和解析（数据图表、解题步骤）作为高级能力按需展开。

**定稿方案**：

- **第一步（先做，零风险）**：调整默认面板组合。
  - 默认视图极简：动画画布 + Timeline + 教师讲解入口。
  - 参数、图表、解题步骤、知识图谱收纳为画布边缘图标，点击展开为抽屉。
  - 三模式切换器从顶栏移除，改为内部状态（记录用户展开了哪些能力，下次保持）。
- **第二步（验证后做）**：结构合并。模式概念彻底退出 UI，"学习/实验/分析"不再作为用户可见的划分——学生的任务只有一个："搞懂这道题"。
- Dashboard / 成就系统保留，入口收进 MenuBar。

**学习体验提升**：首屏认知元素从约 10 个降到约 4 个；界面复杂度随学生熟练度增长，而不是第一天全量压上。

**技术实现需求**（移交工程）：仅调整 panel-manager 默认状态与 AppShell 布局组合逻辑；不删除任何面板组件。

### P3（已定稿）：五色语义系统 —— 规则对用户隐藏

**决策**：确认五色语义系统。颜色规则**不向用户暴露**——不提供颜色设置项、不做颜色说明教程，由系统在各实验、各图层中自动一致地表达。颜色是隐性教学语言，零用户学习成本。

**定稿色表**：

| 语义 | 颜色 | 用途 |
|------|------|------|
| 力 | `#EF4444` 红 | 受力箭头、力的标签 |
| 速度/运动 | `#00D4FF` 青 | 速度矢量、轨迹 |
| 能量 | `#F59E0B` 琥珀 | 能量条、能量转化 |
| 关键事件/行动 | `#FF6B00` 橙 | 碰撞时刻、阶段卡强调、主按钮 |
| 中性结构 | slate 系 | 地面、坐标轴、辅助线 |

同时落地 UI_GUIDELINES：背景 `#0A0E1A` 体系；强调色 `#FF6B00` / `#00D4FF`。

**"隐藏规则"的执行细则**：
- 颜色映射只存在于设计规范与代码常量中，UI 不出现"红色代表力"之类的说明文字。
- 一致性即教学：学生跨实验自然形成"红色箭头=力"的直觉，无需被教。
- 新实验/新模板接入时，由设计与工程按色表执行，不向用户开放自定义（避免破坏语义一致性）。

**学习体验提升**：颜色本身成为跨场景稳定的物理直觉载体，且不增加任何学习成本。

**技术实现需求**（移交工程）：集中在 CSS 变量与 Tailwind 配置层；逐组件替换色值，无逻辑改动。
