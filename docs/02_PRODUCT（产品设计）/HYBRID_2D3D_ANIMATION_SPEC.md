## 1. 背景：为什么动画系统需要重做

### 1.1 S86 质感验证反馈（2026-08-28，项目负责人亲测）

S86（M1-M6）做了动效 token、相机平滑、3D 减负等质感调整，但体验验证暴露的是**更深层的问题**：

| 反馈 | 设计解读 |
|------|----------|
| 相机不够灵活 | 讲解镜头脚本与用户自由观察互相打架，用户不能随时接管视角 |
| 节奏不好掌控 | 播放只有一个"从头播到尾"的节奏，学生无法按自己的理解速度分阶段消化 |
| 动画演示太快，学生会晕头转向 | 默认节奏是按"演示"而非按"教学"设计的；信息出现速度超过初学者消化速度 |
| 视觉效果笨拙 | **根因**：所有题目（包括纯平面问题）都被塞进同一个 3D 渲染路径。二维物理问题强行 3D 化，透视、光照、3D 文字标签反而成为理解负担 |

### 1.2 根因判断

S86 是"在现有 3D 单一路径上做质感微调"，证明这条路已到收益尽头。**问题不在质感参数，在于渲染策略本身**：

- 平面物理问题（自由落体、平抛、受力分析、欧姆定律……）的正确表达是**物理教材式的 2D 矢量动态图解**，不是 3D 场景；
- 只有真正涉及空间结构的问题才需要 3D，且 3D 的职责是**建立空间直觉**，不是承担教学解释；
- 教学解释（为什么运动、为什么受力、公式如何产生）应由 2D 动态图解承担。

这与 FOUNDATION 零号原则的 Hybrid 2D+3D 方向完全一致。本规格是它的正式落地设计。

## 2. 核心设计决策（D1-D4）

### D1：平面问题 → 纯 2D 矢量动态图解

当问题只涉及简单二维运动关系时，**直接生成 2D 教学动画，不经过 3D**。

- 不为平面问题制作 3D 视图（避免维护两套表达、避免"为了高级感强行 3D"）；
- 典型场景：自由落体、平抛/斜抛、直线运动、斜面滑块、受力分析、碰撞、欧姆定律、波动一维传播等。

### D2：空间问题 → 「3D 空间直觉 → 锁定视角 → 2D 图解」叙事流程

当问题涉及明显的空间结构、三维几何关系或空间运动时，使用可切换的 3D+2D 组合：

```
阶段 A：3D 自由观察（建立空间直觉）
   学生拖动鼠标旋转相机，观察真实空间关系
        │
        ▼ 学生旋转到合适角度，点「锁定视角并生成 2D 图解」
阶段 B：视角锁定 → 过渡 → 2D 动态图解（承担教学解释）
   在锁定视角的投影平面上，重新以 2D 矢量图解演示物理过程
```

- 2D 和 3D **不是二选一，也不是两个孤立系统**：3D 负责"它在哪里、长什么样、空间关系是什么"；2D 负责"它为什么这样运动、力是什么、规律是什么"；
- 学生全程可以手动切回 3D 再观察，相机状态保留；
- 典型场景：电动机（线圈在磁场中的空间旋转）、交流发电机、三维电磁场、多物体空间位置关系等。

### D3：同一数据源、同一视觉语言

- 2D 视图与 3D 视图都由 **PhysicsScene 唯一数据源**驱动（架构红线不变）；
- 五色语义系统在 2D/3D 中完全一致（红=力 / 青=速度 / 琥珀=能量 / 橙=关键事件 / slate=中性），学生从 3D 切到 2D 不感觉进入了另一个软件；
- 教学图层四模板（PhaseCard / FormulaStrip / ForceCallout / EventPulse）在 2D 视图中**原生表达**（2D 图解本身就是它们的天然载体），而非叠加在 3D 画布上。

### D4：2D 视图是重新生成的矢量图解，不是"隐藏 3D 模型"

- 2D 视图由 PhysicsScene **重新生成**为扁平矢量表达：物体变几何图形、轨迹变线条、力变箭头、辅助线/虚线/标注按教学需要出现；
- 锁定视角时，2D 图解的空间布局与锁定视角的投影平面**对应**——学生感知到的是"我刚才看的这个场景，从这个角度变成了一张清晰的、会动的物理示意图"，而不是跳到了无关的新画面；
- 禁止把 3D 场景截图/隐藏网格后冒充 2D 视图。

## 3. 视觉语言规格：极简扁平矢量科学可视化

**风格定位**（项目负责人定稿方向）：

> 「极简扁平矢量科学可视化」/「Physics Diagram Motion Graphics」/「Scientific Infographic Motion Graphics」
> 目标不是卡通动画、影视动画、PPT 动画或游戏动画，而是**"会运动的物理示意图"**。

### 3.1 视觉特征

- 扁平化、矢量化、几何化、极简、科学信息图风格、物理教材示意图风格；
- 清晰的空间关系、清晰的运动轨迹、清晰的物理量表达；
- 克制的视觉装饰；流畅、连续、自然的运动；
- 物体优先用**简单几何图形、线条、箭头、虚线、轨迹线、文字标签、符号、适度高亮**表达物理含义；
- **不通过增加元素制造丰富度，而通过运动、空间、节奏和信息层级制造丰富度**；
- 速度、加速度、力、位移、轨迹、能量变化等，优先通过**物体运动、矢量变化、轨迹变化、辅助线和动态标注**表达，而不是只依靠文字说明。

### 3.2 明确禁止

- 卡通动画 / Q 版动画 / 角色动画
- 影视级动画 / 写实 3D / 游戏视觉
- PPT 模板动画 / 大量 UI 装饰
- 大量渐变和复杂光影
- 大量突然出现、突然消失、机械式淡入淡出和 PPT 式转场

### 3.3 色彩与背景

- 沿用已定稿五色语义系统（P3）：力 `#EF4444`、速度/数据 `#00D4FF`、能量 `#F59E0B`、关键事件/行动 `#FF6B00`、中性结构 slate 系；规则对用户隐藏；
- 背景延续深色体系（`#0A0E1A` 系，B1 双轨决策：桌面端深色用于长时间注视）；网格极浅或不用，辅助线一律虚线、低透明度；
- 文字最少化：物理量符号（v、a、G、s）优先于文字说明；文字标注一行不超过 20 字。

### 3.4 动效原则

- 运动必须有合理的时间关系、缓动和连续性（沿用 S86 动效 token：`--dur-enter 250ms` / `--dur-exit 200ms` / `--ease-standard`）；
- 重要物理事件用适度视觉强调（EventPulse 脉冲、高亮），不破坏整体简洁性；
- 每个出现在画面上的元素都必须回答："它帮助学生理解了什么？"——答不上来就删掉（少即是多）。

## 4. 播放节奏重设计（针对"太快 / 晕头转向 / 节奏不好掌控"）

动画节奏按"初学者第一次看"设计，不按"已经懂的人复查"设计。

| # | 规则 | 说明 |
|---|------|------|
| R1 | **首播 = 讲解节奏** | 第一次播放自动采用讲解模式：phase 开始时减速（现有 0.3x/1.2s 机制保留）+ phase 结尾自然停顿（约 0.5-1s 静止帧，让学生消化这一步）；重播时不停顿（连续播放模式） |
| R2 | **默认速度下调** | 基准播放速度从 1.0x 下调（建议 0.8x，具体值走查标定）；慢速档（0.5x/0.25x）必须一键可达 |
| R3 | **分阶段播放控制** | 点击顶部 phase pill = 跳转并单独重播该阶段；提供「重播本阶段」按钮——学生可以"没看懂就只看这一段再来一遍"，不必从头看 |
| R4 | **关键事件静止帧** | EventPulse 后 300ms 静止帧保留（S86 已有）；碰撞等核心事件后延长停顿，给视线落点 |
| R5 | **速度控制显著化** | 播放速度控件常驻 Timeline 旁（不收进菜单），0.25x-2x |

## 5. 相机重设计（针对"相机不够灵活"）

| # | 规则 | 说明 |
|---|------|------|
| C1 | **用户拖动永远优先** | 任何时刻拖动视角立即平滑接管相机（脚本镜头被打断时用缓动让权，不硬切）；拖动后进入"自由镜头"状态，有轻提示可一键"回到讲解镜头" |
| C2 | **讲解镜头/自由镜头** | 画布上提供明确切换：讲解镜头（跟随 camera_script 编排）/ 自由镜头（用户完全控制）；默认讲解镜头，用户一碰即转自由镜头（C1） |
| C3 | **重置视角** | 一键回到当前场景的推荐教学视角 |
| C4 | **锁定视角 → 2D** | 3D 观察阶段（D2 阶段 A）画布主按钮：「锁定视角并生成 2D 图解」；锁定即当前相机投影平面成为 2D 图解的观察平面 |
| C5 | **推荐教学视角** | 进入 3D 观察时默认落在系统推荐的教学视角（camera_script 首帧），学生不操作也能看到合理画面 |

## 6. 2D/3D 判定与切换规则

| 情况 | 默认视图 | 依据 |
|------|----------|------|
| 纯平面运动/受力/电路/一维波动 | 2D 矢量图解（无 3D 阶段） | 2D 已能完整表达物理关系 |
| 涉及空间结构/三维几何/空间运动 | 3D 观察 → 锁定 → 2D 图解（可互切） | 空间直觉只能由 3D 建立 |

- 判定归属：由场景数据标注（PhysicsScene 增量可选字段，如 `teaching_view` 提示，仅追加、向后兼容——与既有 `overlay_hints` 同一扩展原则）；规则解析器按题型给出默认标注；**用户始终可手动切换**；
- 切换必须保留上下文：3D→2D 保留视角对应关系；2D→3D 保留相机位置。

## 7. 3D→2D 过渡体验

- 触发：C4 锁定操作；
- 过渡动画（约 600-800ms，可逆）：光照与深度感渐弱 → 材质压平为纯色 → 物体轮廓线浮现 → 网格/地面退隐 → 辅助线、矢量箭头、标注按教学需要依次淡入；
- 过渡过程本身就是教学："从真实场景抽象出物理模型"——这正是物理建模思想的视觉化，不是普通转场；
- 2D 图解阶段提供「返回 3D 观察」入口，相机状态保留。

## 8. 音效设计

| 项目 | 规格 |
|------|------|
| 事件音效 | 小球碰撞、弹簧压缩/释放、开始运动、关键事件发生、实验操作反馈（点击/切换确认音） |
| 克制原则 | 只对**物理事件与操作确认**发声；无持续背景音；不为所有动作强行配音；不用声音掩盖糟糕的动画反馈 |
| 全局开关 | 设置页音效总开关 + 画布快捷开关；**建议默认关闭**（克制原则，待项目负责人确认） |
| 完整性红线 | 关闭音效后，动画本身必须能完整表达物理意义——音效只是增强层，不是教学核心 |

## 9. 与现有系统的关系（不变量）

- **PhysicsScene 唯一数据源不变**；overlay_hints / TeachingScript 生成器 / 校验器 / AI 润色管线全部延续（它们产出的教学脚本同时驱动 2D 图解与 3D 视图）；
- 教学图层四模板延续，在 2D 视图中原生表达；
- 18 个内置实验全部保留：平面类实验获得 2D 图解视图（迁移优先级最高），空间类实验获得"3D→锁定→2D"流程；
- Timeline、面板体系、五色语义、动效 token、prefers-reduced-motion 降级链全部延续；
- 诚实失败守卫（教学红线）不变。

## 10. 工程实现需求（移交要点；技术选型归工程实现 Agent）

1. **2D 矢量渲染层**：由 PhysicsScene 驱动生成扁平矢量动画（SVG/Canvas 等技术路线由工程评估）；必须遵守 Teaching Layer 既有原则——**state = f(t) 纯函数渲染，拖动/跳转 Timeline 确定性回放**；
2. **视角锁定 → 2D 生成管线**：锁定相机投影平面 → 场景实体/轨迹/力在该平面重新矢量表达；
3. **播放节奏系统**：R1-R5（讲解节奏、默认速度、分阶段重播、静止帧、常驻速度控制）；
4. **相机系统**：C1-C5（用户优先接管、双镜头模式、重置、锁定、推荐视角）；
5. **音效系统**：轻量实现 + 全局开关，默认关闭；
6. **场景视图标注**：PhysicsScene 可选增量字段（仅追加），规则解析器按题型输出默认标注；
7. **迁移策略**：建议按"平面类实验 2D 化 → 空间类实验锁定流程 → 新题目默认路径"的顺序分 Sprint 推进；
8. **约束**：验证门禁保持全绿；不改物理计算逻辑；不改 PhysicsScene 现有字段；不动 01_FOUNDATION。

## 11. 验收要点（设计侧走查用）

1. 平面问题（如自由落体、欧姆定律）：默认呈现 2D 矢量动态图解，无 3D 阶段；图解符合第 3 节风格规格（扁平、矢量、少即是多）；
2. 空间问题（如电动机）：阶段 A 可自由旋转观察；锁定视角后过渡自然；2D 图解空间布局与锁定视角对应，无"跳戏感"；可切回 3D 且相机状态保留；
3. 节奏：首播讲解节奏可感知（phase 减速+停顿），分阶段重播可用，速度控件常驻；
4. 相机：拖动即时接管不打架，回到讲解镜头一键可达；
5. 2D/3D 视觉语言统一：五色语义一致、模板一致，切换无软件割裂感；
6. 音效：仅事件发声、全局开关生效、关闭后教学表达完整；
7. 教学红线：每 phase 信息量克制（1 卡 + ≤1 公式条 + ≤3 标注 + ≤2 脉冲）在 2D 视图中同样成立。
