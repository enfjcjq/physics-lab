## 2. Teaching Layer 第一批模板规格（P1）

### 2.1 总体机制

- 2D 教学图层为 HTML/SVG 绝对定位层，叠加在 3D 画布上，`pointer-events: none`（不遮挡 3D 交互；自身控件除外）。
- 图层完全由 Timeline 当前时间驱动：**拖动/跳转 Timeline 时，图层内容必须确定性回放到对应状态**（纯函数式渲染：state = f(t)，不依赖播放历史）。
- 所有教学元素在学习场景页提供统一显隐开关（原则十二）。
- 低性能/未配置场景降级：图层整体关闭，退回现有侧面板联动。

### 2.2 模板一：PhaseCard 阶段卡

**作用**：告诉学生"现在进行到哪一步、这一步在发生什么"。

**数据模型**：
| 字段 | 来源 | 说明 |
|------|------|------|
| `title` | timeline `phase_start` 事件的 label | 如"阶段 2：自由下落" |
| `hint` | 事件的 description（可选） | 一句话解释，不超过 30 字 |
| `phase_index / total` | timeline 事件序列 | 显示"第 2/4 阶段" |

**触发与联动**：
- 触发：`phase_start` 事件帧。
- 出现时动画自动减速至 0.3x，持续 1.2 秒后恢复原速（**不强制暂停**，避免打断心流；用户可在设置中改为"阶段开始时暂停"）。
- 卡片最短展示 1.5s；phase 结束时 200ms 淡出。

**视觉规格**：
- 位置：画布左上角，距边 16px。
- 结构：左侧 3px 竖条 `#FF6B00` + 深色卡片底 `slate-900/85` + backdrop-blur；圆角 12px；padding 12px 16px。
- 文字：标题 14px 半洁白；hint 12px `slate-400`；阶段序号 10px `slate-500`。
- 动效：进入 fade + 下移 8px，250ms ease-out；退出 fade 200ms。

### 2.3 模板二：FormulaStrip 公式推导条

**作用**：展示"公式如何产生"——式子 → 代入数值 → 高亮结果，与动画时刻严格同步。

**数据模型**：
| 字段 | 来源 | 说明 |
|------|------|------|
| `equation_id` | 引用 `scene.equations[].id` | 取 LaTeX 表达式与变量定义 |
| `reveal_stages` | 模板内规则 | 三阶段：原始公式 → 代入当前参数值 → 结果高亮 |
| `highlight` | 模板内规则 | 结果用 `#FF6B00`，变量符号用 `#00D4FF` |

**触发与联动**：
- 在该公式所属 phase 内分阶段展开：phase 进度 0% 显示原式，50% 代入数值，80% 高亮结果（比例可按 phase 时长微调）。
- Timeline 拖动时按上述规则确定性重建（state = f(t)）。
- 无对应 equation 数据的 phase 不显示本模板（自动隐藏，不留空壳）。

**视觉规格**：
- 位置：画布底部居中，距 Timeline 上方 12px，最大宽度 560px。
- 渲染：KaTeX；底色 `slate-900/80` + backdrop-blur，圆角 12px，padding 10px 20px。
- 阶段切换动效：新内容 200ms 淡入，不做位移（公式区域稳定，避免视觉跳动）。

### 2.4 PhysicsScene 追加字段建议（`overlay_hints`，可选）

```ts
// 仅追加、向后兼容；缺省时 Teaching Layer 按默认规则从 phases/equations 推导
export interface OverlayHints {
  phase_cards?: Array<{
    phase_id: string;        // 对应 timeline phase_start 事件 id
    title?: string;          // 缺省用事件 label
    hint?: string;           // 缺省用事件 description
  }>;
  formula_strips?: Array<{
    phase_id: string;        // 该公式条归属的 phase
    equation_id: string;     // 引用 equations[].id
  }>;
}
```

设计意图：短期规则解析器可不填此字段（默认推导即可）；长期由 AI 在"选择+组合模板"时输出此结构。**不修改任何现有字段。**

## 6. S72 模板规格（ForceCallout / EventPulse）

> 本节为 S72 实施依据，S71 不涉及。

### 6.1 模板三：ForceCallout 受力标注

**作用**：解释"为什么受力"——在力出现的时刻，把力的名称与大小公式标注在受力箭头旁边。

**数据模型**：
| 字段 | 来源 | 说明 |
|------|------|------|
| `label` | `forces[].visual.label` / `description` | 如"重力 G" |
| `formula` | `forces[].magnitude` | 如 `G = mg`；为表达式字符串时直接展示 |
| `color` | 固定 `#EF4444`（P3 语义） | 忽略场景自定义色，保证语义一致 |
| `anchor` | `forces[].target_entity` + 箭头方向 | 锚定 3D 受力箭头根部 |

**触发与联动**：
- 常量力：所属 phase 开始 0.5s 后淡入；`force_change` 事件帧：对应标注 200ms 淡入/淡出切换。
- 空间跟随：标注为屏幕空间 2D 元素，每帧由 3D 箭头根部坐标投影得出位置（不参与透视缩放），镜头运动时平滑跟随（lerp，避免抖动）。
- 同屏上限 3 个；超出时按当前力的大小排序取前 3，其余收进"…"角标。
- 拖动 Timeline：按 state = f(t) 重建（哪些力在 t 时刻存在即显示哪些）。

**视觉规格**：文字 12px 白 + 公式 KaTeX；底色 `slate-900/75`，圆角 8px，padding 4px 8px；与箭头间 1px 引导线（`#EF4444`，40% 透明度）。

### 6.2 模板四：EventPulse 事件标记

**作用**：强化教学关键时刻（碰撞、射出、换向、最大位移），让学生注意到"这里发生了什么"。

**数据模型**：
| 字段 | 来源 | 说明 |
|------|------|------|
| `event` | `timeline.events`（collision / state_change / trigger） | 事件帧与描述 |
| `text` | 事件 `description` | 一行解释，≤20 字 |

**触发与联动**：
- 事件帧触发：事件世界坐标处橙色脉冲圈扩散（屏幕空间，#FF6B00，半径 0→40px，600ms ease-out，透明度渐隐）。
- 同步：画布底部居中浮现一行解释文字，2s 后淡出；Timeline 对应事件节点同步闪烁一次。
- **克制原则**：只标记教学关键事件，每个 phase 至多 2 个（由场景数据中的事件重要性或 `overlay_hints` 指定；缺省规则：collision 必标，其余按 phase 内顺序取前 1 个）。
- 拖动 Timeline 经过事件帧不重复触发脉冲（脉冲是播放态表现，非状态）；但解释文字状态由 f(t) 决定（事件后 2s 窗口内可见）。

### 6.3 `overlay_hints` 扩展（S72 追加，同样仅追加可选字段）

```ts
export interface OverlayHints {
  // ...v1.0 字段（phase_cards / formula_strips）不变
  force_callouts?: Array<{
    force_id: string;          // 引用 forces[].id；缺省=全部力按默认规则显示
    formula_override?: string; // 覆盖显示公式
  }>;
  event_pulses?: Array<{
    event_id: string;          // 引用 timeline.events[].id
    text_override?: string;    // 覆盖解释文字
  }>;
}
```

## 7. P2 信息架构：第一步规格与第二步验证标准

### 7.1 第一步规格（S72，零风险）

- 学习场景页默认开合：3D 画布 + Timeline + TeacherPanel；其余面板（problem / parameters / analysis / charts）默认**关闭**。
- 画布左缘放置 4 个竖排图标入口：参数、图表、步骤、图谱（图标 + 悬停文字，点击展开为对应抽屉，再点收起）。
- 顶栏三模式切换器**移除**；用户的面板展开组合记忆到 localStorage，下次进入保持。
- MenuBar 保留全部原有功能入口；Dashboard/成就入口收进 MenuBar。

### 7.2 第二步验证标准（何时启动结构合并）

满足以下全部条件，才启动"模式概念彻底退出 UI"的结构合并：

| 指标 | 达标线 | 测量方式 |
|------|--------|----------|
| 核心路径效率 | 新用户从启动到看完一遍教学动画 ≤ 3 次点击 | 新用户走查（负责人模拟 + 至少 3 名学生试用） |
| 功能可发现性 | 4 个抽屉图标中无"零发现"图标（试用中每个图标至少被主动点开 1 次） | 试用观察 + 简单打点 |
| 无阻塞反馈 | 无"找不到某功能"类 P0/P1 反馈 | 试用访谈记录 |

未达标：调整默认组合或入口位置后重新走查，不强行合并。

**首次走查结果（2026-08-05）**：指标 ① 通过；指标 ②③ 未达标（IconRail 纯图标零发现；MenuBar 菜单项文字截断）。**结论：结构合并不启动**，进入 S80 修复（IconRail 常驻文字标签 48→64px、MenuBar 禁止文字裁切+空间不足折叠「更多」、导出入口深置），修复后复走查。

**复走查结果（2026-08-08）**：✅ 三项指标全部达标（四图标 clicks 7-10 次，全部被发现并多次使用）。**结构合并正式放行（S81）**，合并完成后做一次确认走查收口。

### 7.3 S72 验收要点（设计侧）

1. ForceCallout：力出现/消失与动画时刻同步；镜头旋转时标注跟随稳定无抖动；同屏超 3 个正确收敛。
2. EventPulse：脉冲只在播放经过事件帧时触发；拖动 Timeline 不重复触发；解释文字按时间窗正确显隐。
3. 第一步默认开合生效；展开组合可记忆；三模式切换器已移除且原功能全部可达。

## 8. S71 验收纪要（2026-08-04，设计侧走查结论）

**结论：S71 设计验收通过。** 以下实施偏差经评估全部批准，作为规格的有效补充：
