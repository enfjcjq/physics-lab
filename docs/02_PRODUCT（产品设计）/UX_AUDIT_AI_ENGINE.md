## 0. 审计结论（一句话）

> 当前产品是一个**优秀的"交互式物理实验平台"**，但还**不是**"AI 物理教学动画生成引擎"。
> 用户打开产品后首先看到的是"18 个实验的模拟器"，而不是"输入一道题，看它活过来"。
> 核心主线（输入题目 → AI 生成教学动画）在 UI 上不是第一路径——这是当前最大的体验问题。

---

## 1. 现状审计：与核心定位的三个错位

### 错位 1：入口错位 —— 产品"首页"是模拟器，不是题目输入

**事实**（基于 `App.tsx` / `AppShell.tsx` 代码）：
- 应用启动后直接加载上次的实验插件（默认自由落体），用户第一眼看到的是 3D 场景 + 面板群。
- 题目输入（含 OCR）已存在，但只是左侧面板中的一个功能，不是主路径。
- 顶栏最显眼的控件是"实验切换器"（18 个实验下拉列表）——这是模拟器产品的信息架构。

**与定位的冲突**：核心闭环是"**题目驱动**"，而当前 UI 是"**实验驱动**"。学生带着一道不会的题来，却被要求先"选一个实验"。

### 错位 2：动画是"演示运动"，还不是"解释为什么"

**事实**：
- 3D 场景已有：实体、轨迹、受力箭头、HUD、碰撞粒子——属于"展示物体如何运动"。
- PhysicsScene 数据结构**已经具备**教学叙事所需的全部字段：`timeline.phases`、`teacher_steps`、`equations`、`camera_script`。
- 但渲染层还没有"阶段化教学叙事"：没有阶段标题卡、没有"为什么"的自动讲解提示、没有公式随时间推导的呈现。
- **Hybrid 2D + 3D 尚未实现**：目前只有 3D 场景 + 独立面板，没有"讲解时切换/叠加 2D 教学视角"的能力。

**与定位的冲突**：视觉方向要求"3D 理解空间结构，2D 理解公式、受力和过程"。当前的 2D 信息（公式、步骤）躺在侧边面板里，与动画时刻脱节。

### 错位 3：界面信息密度偏高，偏离"少即是多"

**事实**：首屏同时存在——MenuBar、三模式切换（学习/实验/分析）、实验切换器、左面板、右面板、教师面板、底部抽屉、Timeline、Dashboard 弹层、成就 Toast。对第一次打开的学生，认知负担重。

**与定位的冲突**：PRODUCT_PRINCIPLES 第十一条："学生第一次打开就知道如何使用"。

## 2. 设计方案

以下每个提案均包含五要素：① 用户问题 ② 为什么修改 ③ 修改方案（含 A/B 对比与推荐） ④ 学习体验提升 ⑤ 技术实现需求。
**所有提案不修改物理计算逻辑、不改变基础架构**（PhysicsScene 数据驱动、Timeline 驱动、插件系统均保持不变），改动集中在渲染层与信息架构。

---

### 提案 P0：重构核心路径 —— "题目优先"的新首屏

**① 用户问题**：学生带着一道物理题打开软件，看到的却是实验列表，需要自己反推"我的题对应哪个实验"。核心卖点（输入题目自动生成动画）被埋在二级功能里。

**② 为什么修改**：这是 Priority 1 闭环（题目 → PhysicsScene → 教学动画）在 UI 上的直接体现。入口错位会让用户把产品理解为"又一个模拟器"，护城河能力无法被感知。

**③ 修改方案**：

**方案 A（推荐）：题目输入成为启动首页**
```
启动
 ↓
┌─────────────────────────────────────┐
│  "把不会的物理题放进来"               │
│  ┌───────────────────────────────┐  │
│  │  输入题目文字 / 拍照(OCR)       │  │   ← 首屏唯一主角
│  └───────────────────────────────┘  │
│  [开始生成教学动画]                   │
│                                      │
│  最近题目 ▸    示例题目 ▸    实验库 ▸ │   ← 次级入口，折叠
└─────────────────────────────────────┘
 ↓ 生成中：分步进度（识别实体 → 建模 → 编排动画）
 ↓
学习场景页（教学动画 + Timeline + 讲解）
```
- 优点：核心路径零歧义；与"30 秒生成教学动画"的愿景完全一致；实验平台能力全部保留（降级为"实验库"入口）。
- 缺点：改动涉及首屏路由逻辑；老用户（已习惯实验切换）需要适应。

**方案 B：保留实验页为首屏，顶部强化"输入题目"大按钮**
- 优点：改动小、风险低。
- 缺点：本质仍是模拟器架构，核心主线依旧不是第一路径，治标不治本。

**推荐：方案 A。** 判断标准：删除"题目输入首页"，学生还能感受到这个产品和 PhET 的区别吗？不能。所以它是核心能力，应占据首屏。

**④ 学习体验提升**：学生的真实场景是"作业里有一道题不懂"。方案 A 让产品从"我来逛实验"变成"我的题活了"，学习动机路径最短。

**⑤ 技术实现需求**：
- 新增一个首屏组件（题目输入 + OCR 入口 + 最近题目列表），复用现有 problem-input 与 OCR 能力，不新增 AI 依赖。
- 页面切换由现有 Zustand 状态驱动（沿用无 React Router 约定）。
- 生成过程展示分步进度（现有 progress 事件已支持）。
- **不需要**改动 PhysicsScene 结构、解析器、插件系统。

### 提案 P1：教学动画体验 —— 阶段化叙事 + 2D 教学图层（Hybrid 2D+3D 落地）

**① 用户问题**：学生看着小球下落、线圈转动，"看到了运动"但不知道"为什么这样运动、该关注什么、公式从哪来"。当前动画≈精美的演示，不是讲解。

**② 为什么修改**：Priority 2 的核心是"动画是否帮助学生理解"。数据结构上 phases / teacher_steps / equations 早已就绪，缺的是**呈现层设计**——这是纯设计问题，不是技术瓶颈。

**③ 修改方案**：

**方案 A（推荐）：2D 教学图层叠加在 3D 画布上（Manim 式）**
- 在 3D 画布上叠加一个 2D HTML/SVG 图层，由 Timeline 驱动：
  - **阶段卡**：每个 phase 开始时，左上角淡入阶段标题（如"阶段 2：磁通量变化，感应电流产生"），动画自动减速或暂停一拍。
  - **受力标注**：箭头旁直接出现 2D 标签（G = mg），随镜头保持可读，不参与 3D 透视变形。
  - **公式推导条**：画布底部/侧缘，公式随时间逐步"长出来"（先 v = gt，再代入数值，再高亮结果），与动画时刻严格同步。
  - **镜头语言**：讲解受力时镜头自动推近（camera_script 已有该数据），3D 负责"看清空间关系"，2D 图层负责"讲清为什么"。
- 优点：信息出现在它解释的物体旁边（Manim 的核心手法）；学生视线不用在 3D 场景和侧面板之间来回跳；2D/3D 各司其职，正是修正版原则的落地。
- 缺点：需要一套 Timeline → 2D 图层的同步机制；图层内容需要按 phase 配置（短期可用规则模板，长期由 AI 生成）。

**方案 B：保持 3D 场景不变，强化侧面板与 Timeline 联动（面板高亮当前步骤）**
- 优点：实现成本最低，全是现有面板的联动增强。
- 缺点：信息仍与场景空间分离，学生要在两个区域之间转移注意力；不是 Hybrid 2D+3D，是"3D + 旁边的文字"。

**推荐：方案 A 为主体，方案 B 作为降级 fallback**（低性能设备或图层未配置的实验自动退回面板联动）。

**④ 学习体验提升**：从"看运动"升级为"被带着理解"：阶段卡告诉学生"现在进行到哪一步"，2D 标注解释"为什么"，公式推导条展示"规律如何产生"。这正是原则二十描述的目标体验。

**⑤ 技术实现需求**：
- 新增"2DOverlayLayer"渲染组件（纯渲染层，订阅 Timeline 当前时间与 phase 事件）。
- 图层内容 schema 可复用现有 `timeline.events` + `equations` + `forces` 字段；如需新增字段，只**追加**到 PhysicsScene，向后兼容（建议与工程 Agent 确认后追加 `overlay_hints` 可选字段）。
- 阶段自动暂停/减速由 Timeline 播放控制扩展实现，不改物理计算。
- 组件必须支持"显示/隐藏"开关（原则十二：教学内容可自由控制）。

### 提案 P2：信息架构简化 —— 从"三模式"到"一个学习场景"

**① 用户问题**：新用户面对 学习/实验/分析 三个模式 + 六个可开关面板，不知道先看哪里。模式之间的区别（学习 vs 实验）对学生并不自明。

**② 为什么修改**：原则十一（少即是多）与十九条（拒绝功能堆砌）。三模式是"功能视角"的划分，不是"学生任务视角"的划分——学生的任务只有一个："搞懂这道题"。

**③ 修改方案**：

**方案 A（推荐）：单一场景页 + 渐进式展开**
- 默认视图极简：动画画布 + Timeline + 一个"老师讲解"入口。
- 其余能力（参数调节、数据图表、解题步骤、知识图谱）收纳为画布边缘的四个图标，点击才展开为抽屉。
- "学习/实验/分析"三模式降级为内部状态（控制默认展开哪些抽屉），不再作为顶栏一级开关。
- 优点：首屏认知元素从 ~10 个降到 ~4 个；高级能力全部保留，按需出现。
- 缺点：模式切换的既有用户习惯被打破；需要重新设计抽屉的默认开合规则。

**方案 B：保留三模式，仅优化默认面板组合（学习模式默认只开教师面板）**
- 优点：改动最小。
- 缺点：一级开关仍在，"学生该选哪个模式"的困惑仍在。

**推荐：方案 A，但分两步走**——第一步先做方案 B（调整默认开合，零风险），验证后再做方案 A 的结构合并。

**④ 学习体验提升**：注意力回归动画本身；界面复杂度随学生熟练度增长，而不是第一天就全量压上。

**⑤ 技术实现需求**：仅调整 panel-manager 的默认状态与 AppShell 的布局组合逻辑，不删除任何面板组件。Dashboard/成就系统保留，入口收进 MenuBar。

### 提案 P3：视觉系统对齐 UI_GUIDELINES

**① 用户问题**：当前视觉（slate/sky 蓝灰系）与 UI_GUIDELINES 定义的色板不一致，缺少统一的强调色体系，"受力、能量、关键事件"等教学语义没有固定的颜色语言。

**② 为什么修改**：原则十三（视觉统一）。教学产品里颜色是**语义工具**（红色=力、蓝色=速度……），不只是装饰；颜色语言不统一会增加理解成本。

**③ 修改方案**（无需 A/B，属于规范落地）：
- 背景落地 `#0A0E1A` 体系；强调色采用 `#FF6B00`（行动/关键事件）+ `#00D4FF`（信息/数据）。
- 建立**教学语义色表**（建议值，待确认）：

| 语义 | 颜色 | 用途 |
|------|------|------|
| 力 | `#EF4444` 红 | 受力箭头、力的标签 |
| 速度/运动 | `#00D4FF` 青 | 速度矢量、轨迹 |
| 能量 | `#F59E0B` 琥珀 | 能量条、能量转化 |
| 关键事件/行动 | `#FF6B00` 橙 | 碰撞时刻、阶段卡、主按钮 |
| 中性结构 | slate 系 | 地面、坐标轴、辅助线 |

- 所有受力箭头、图表曲线、HUD 逐步迁移到该色表。

**④ 学习体验提升**：学生跨实验形成稳定的视觉直觉——"红色箭头=力"，颜色本身成为教学语言。

**⑤ 技术实现需求**：集中在 CSS 变量与 Tailwind 配置层；逐组件替换色值，无逻辑改动。

## 3. 优先级与实施顺序建议

| 顺序 | 提案 | 对应官方优先级 | 风险 | 建议 Sprint |
|------|------|----------------|------|-------------|
| 1 | P0 题目优先首屏 | Priority 1 | 中 | S70 |
| 2 | P1 阶段化叙事 + 2D 图层（先做阶段卡+公式条，受力标注第二批） | Priority 2 | 中 | S70-S71 |
| 3 | P2 信息架构简化（先默认面板组合，后结构合并） | Priority 3 | 低→中 | S71 |
| 4 | P3 语义色表落地 | 贯穿 | 低 | 随各提案顺带执行 |

**明确不做**（避免范围蔓延）：不改物理计算逻辑、不动插件系统、不为视觉效果新增技术组件（如着色器拖尾暂缓——"炫酷"不优先于"讲清楚"）。
